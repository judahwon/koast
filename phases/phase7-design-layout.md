# 목표

koast(한국해양기상기술) 사이트의 **전 페이지 디자인과 레이아웃을 재구성**한다.
기준점은 두 개다.

1. **`src/assets/images/App.png`** — 이 프로젝트의 Figma 홈 목업(1920×4302). **무엇을 만들지에 대한 도면이다.**
   아래 "기준점 상세"의 수치는 전부 이 파일에서 픽셀 단위로 실측한 값이므로 상상으로 덮어쓰지 마라.
2. **NHN Cloud (nhncloud.com/kr)** — **얼마나 잘 만들지에 대한 품질 기준이다.**
   B2B 기술기업 사이트의 정보 밀도, 카드 그리드 규율, 섹션 리듬을 여기에 맞춘다.

"동작하는 수준"이 아니라 "App.png를 나란히 놓고 비교해도 밀리지 않고, NHN Cloud 옆에 놓아도
아마추어로 보이지 않는 수준"이 목표다.

## 기술 스택 못박기

- **Astro 7 SSG + React 19 아일랜드 + Tailwind v4.** 이 스택을 바꾸지 않는다.
- **새 npm 의존성을 추가하지 않는다.** 모션은 CSS transition/animation + IntersectionObserver 로만 구현한다.
  framer-motion, GSAP, AOS 등 어떤 애니메이션 라이브러리도 설치 금지.
- 새 컴포넌트는 기본적으로 `.astro`. 클라이언트 상태가 반드시 필요한 것만 `.tsx` + `client:load`.
- `CLAUDE.md` 의 모든 규칙이 그대로 유효하다. 작업 시작 전에 반드시 정독한다.

## 절대 제약 — koast 코드베이스 규칙 (어기면 빌드/린트가 깨진다)

`CLAUDE.md` 에 전부 있다. 아래는 이번 작업에서 특히 자주 어길 것들이다.

1. **시맨틱 토큰만 쓴다.** `bg-blue-600`, `text-zinc-700` 같은 raw 팔레트 유틸 금지.
   새 색이 필요하면 컴포넌트에 hex 를 박지 말고 `src/styles/global.css` 에 토큰을 추가한다.
2. **`@theme inline` 을 `@theme` 로 바꾸지 않는다.**
3. **모든 내부 링크는 `${ SITE.base }` 를 앞에 붙인다.** `href="/blog"` 로 쓰면 배포본에서 깨진다.
   React 아일랜드는 `import.meta.env.BASE_URL` 을 직접 읽지 말고 prop 으로 받는다.
4. **ESLint 포맷 규칙** — 템플릿 리터럴 안 공백(`` `${ SITE.base }/blog` ``),
   JSX 문자열 prop 도 중괄호(`className={'flex'}`), 싱글 쿼트, 세미콜론, 2칸 들여쓰기,
   멀티라인 trailing comma, 연산자는 줄 앞.
5. **긴 class 문자열은 한 줄 백틱.** 따옴표로 쪼개 잇거나 중괄호 안에서 줄바꿈하지 않는다.
6. **주석은 최소한.** 왜 그렇게 했는지가 코드에 안 드러날 때만 한 줄로. 섹션 배너 주석 금지.
7. **콘텐츠는 컴포넌트가 아니라 `src/data/*.ts` 에서.**
8. **`npm run dev` / `npm run build` 를 임의로 실행하지 않는다** — 단, 아래 "검증" 절의
   예외 규정을 따른다.

## 이번 작업에서 확정된 사양 (사용자 결정 사항 — 협상 대상 아님)

- **정보구조(IA)는 현재 그대로 유지한다.** `회사소개 / 서비스 / 블로그 / 채용 / 문의` 5개.
  목업 네비에 있는 `프로젝트`·`연혁` 은 만들지 않는다. `블로그` 를 제거하지 않는다.
  목업에서 가져오는 것은 **비주얼 언어(색·타이포·간격·컴포넌트 패턴)뿐**이고,
  그 비주얼 언어를 **전 페이지에 이식**하는 것이 이번 작업이다.
  단, 헤더 우측의 `문의하기` CTA 버튼은 목업대로 추가한다.
- **다크모드를 완전히 제거하고 라이트 전용으로 정리한다.**
  `global.css` 의 `.dark` 블록, `@custom-variant dark`, `Navigation.tsx` 의 테마 토글,
  `BaseLayout.astro` 의 FOUC 방지 인라인 스크립트, `localStorage['theme']` 를 전부 걷어낸다.
  3계층 토큰 구조(`:root` → `@theme inline` → `@theme`) 자체는 유지한다.
- **에셋은 이미 추출되어 `src/assets/images/home/` 에 있다.** 새로 만들거나 외부에서 받지 마라.

## 병렬로 진행할 것 (서브에이전트 팬아웃)

**주의: 아래 팬아웃은 "순차로 진행할 것" 단계가 완전히 끝난 뒤에만 시작한다.**
토큰과 레이아웃 셸이 확정되지 않은 상태에서 병렬로 들어가면 전부 다시 만들어야 한다.

토큰이 확정된 뒤에는 아래가 서로 독립이다. 각각 별도 서브에이전트에 배분해 동시에 진행해.

- **홈 섹션 A** — `Hero.astro` + 파트너 로고 마퀴
- **홈 섹션 B** — Business Area 3카드 + Stats 타일/자격 pill
- **홈 섹션 C** — Solutions 가로 아코디언 (유일하게 `.tsx` 아일랜드가 필요한 곳)
- **홈 섹션 D** — Contact CTA 밴드 (CSS 그라디언트 + SVG blob)
- **하위 페이지 A** — `about.astro` + `services.astro` 및 그 하위 컴포넌트
- **하위 페이지 B** — `blog/` + `careers/` 목록·상세 및 `BlogPostLayout.astro`
- **하위 페이지 C** — `contact.astro` + `ContactForm.tsx` + `404.astro`

## 순차로 진행할 것 (쪼개지 마)

**`global.css` 토큰 체계 → `constants.ts` → `BaseLayout`/`PageLayout`/`Header`/`Footer`/`Navigation.tsx`
→ `src/data/*.ts`** 이 덩어리는 **한 에이전트가 처음부터 끝까지** 맡는다.

이유: 이 파일들은 같은 상태에 쓰기(write)를 한다.

- 다크모드 제거가 `global.css`(`.dark` 블록·`@custom-variant`), `Navigation.tsx`(토글 UI·localStorage),
  `BaseLayout.astro`(FOUC 스크립트) **세 파일에 동시에 걸쳐 있다.** 하나만 지우면 나머지가 깨진다.
- 새 컬러 토큰의 **이름**이 이후 모든 컴포넌트가 참조할 네임스페이스다. 이름이 흔들리면
  팬아웃된 7개 작업이 전부 서로 다른 토큰을 쓴다.
- `NAV_LINKS` 변경(문의하기 CTA 분리)이 `Header`·`Navigation` 양쪽 렌더에 영향을 준다.
- `src/data/*.ts` 는 홈과 하위 페이지가 **동시에 읽는다.** 스키마가 바뀌면 양쪽이 같이 깨진다.

여기를 병렬로 쪼개면 부분별로는 그럴싸해 보여도 이음매에서 버그가 난다.
특히 **토큰 이름 불일치**는 lint 도 build 도 잡아주지 않고 화면에서만 티가 난다.

## 검증

만드는 에이전트와 **별개의** 검증 에이전트를 둬라. **자기가 만든 걸 자기가 채점하지 마라.**
검증자는 아주 가혹한 비평가여야 한다.

### 렌더링 검증 (필수 — 코드만 읽고 채점하는 것을 금지한다)

검증자는 **반드시 실제 렌더링된 픽셀을 보고 판정한다.** CSS 를 읽고 스크린샷을 상상해서 채점하지 마라.

`CLAUDE.md` 의 "Claude 는 dev 서버를 임의로 실행하지 않는다" 규칙의 목적은 ①사용자의 dev 서버를
포트 충돌로 죽이지 않는 것 ②`dist/` 를 덮어쓰지 않는 것 두 가지다.

**이미 사용자의 dev 서버가 4321 에 상주 중이므로(Astro 7 은 두 번째 인스턴스를 거부한다) 아무것도
새로 띄우지 않고 그 서버를 캡처만 한다.** 규칙의 두 목적이 그대로 지켜진다.
`npm run build` 는 c8 검증에서만 실행한다.

```bash
npx astro dev status           # 상주 서버 확인. 죽이거나 재시작하지 않는다.
"C:\Program Files\Google\Chrome\Application\chrome.exe" --headless=new --disable-gpu \
  --no-sandbox --hide-scrollbars --virtual-time-budget=6000 --window-size=1440,987 \
  --screenshot=shot.png "http://localhost:4321/"
```

- `--window-size` 높이에서 약 87px 을 뺀 값이 실제 뷰포트다 (1440×987 → 1440×900).
  이걸 모르면 캡처 하단의 빈 여백을 레이아웃 버그로 오인한다.
- 캡처 뷰포트는 **1920 / 1440 / 768 / 375** 네 폭 전부. 목업 실측값은 1920 기준이다.
- 전 페이지(`/`, `/about`, `/services`, `/blog`, `/careers`, `/contact`)를 캡처한다.
- dev 서버는 base 가 `/` 이고 빌드는 `/koast` 다. `${ SITE.base }` 누락은 렌더링이 아니라
  **grep 과 `npm run build` 로** 잡는다.

검증자는 캡처와 `src/assets/images/App.png` 를 **나란히 놓고** 판정한다.

### 체크리스트 — 전 항목 Yes 여야 통과

### 검증자 운영 규칙

- **판정은 받아들이고, 처방은 검토한다.** 검증자는 채점자이지 설계자가 아니다.
  검증자가 제안한 수정이 다른 체크리스트 항목을 깨뜨리면 그 처방은 기각하고 판정만 남긴다.
  통과 조건은 전 항목 Yes 이므로 항목 하나를 고치며 다른 항목을 깨는 교환은 손해다.
- **원리적으로 해결 불가능한 제약은 실패가 아니라 "수용된 제약"으로 따로 기록한다.**
  (예: 목업의 3D 일러스트가 래스터라 특정 배율에서 부드럽지 않음 — 벡터 원본이 없으므로 해결 불가)
  이걸 실패로 계속 올리면 아래 정체 감지 규칙이 잘못 발동한다.
- 점수보다 **항목별 판정**을 신뢰한다. 보고에는 항목별 통과/실패와 근거 수치를 쓴다.

```bash
git add -A && git commit -m "refactor: round 3 - 레이아웃 그리드를 목업 실측값에 맞춘다 (74 -> 78)"
```

마지막 라운드 후 검증자에게 이것을 물어 기록한다:

> App.png 수준에 도달하는 것이 물리적으로 가능한가?

**같은 지적이 3라운드 연속 반복되면 접근 방식이 틀린 것이다. 멈추고 보고한다.**
